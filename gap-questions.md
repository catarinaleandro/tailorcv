# Gap questions

Ask after evidence matching and before building the CV. Goal: surface real experience the profile misses, never to coax claims.

## Triggers
| Trigger | Condition | Template |
|---|---|---|
| T1 Must-have with no evidence | Requirement status GAP | The posting requires {requirement}. Describe a time you did this, even in a course or side project. What did you do and what was the result? |
| T2 Vague evidence | Matched bullet has no metric or scope | Your entry says "{bullet}". Can you add a number: users, time saved, size, revenue, or scale? |
| T3 Same skill, different wording | Requirement PARTIAL | They ask for {requirement}. Does {entry} count? What exactly did you do? |
| T4 Missing expected section | Posting expects certifications, tools, publications or languages not in profile | This role values {item}. Do you have anything to add (certificates, tools, languages)? |
| T5 Inconsistency | Overlapping dates, missing dates, unclear titles | Your profile has {conflict}. Which is correct? |

## Rules
1. Ask for evidence, not yes/no. Never ask "Do you have X experience?".
2. Maximum 5 questions, ranked: must-have gaps first, then vague evidence on must-haves, then nice-to-haves.
3. Never ask something the profile already answers. Check first.
4. Always offer "I don't have this". Record it as a confirmed gap. Never pressure the user.
5. Ask one question at a time unless the user prefers a batch.
6. Save every answer to profile.yaml as a new entry with `source: user-confirmed` and a new ID, so the auditor can trace it.
7. Track for evaluation: questions asked, and how many produced a usable new bullet.
